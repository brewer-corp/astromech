## Finding 3: Drive the new fleet-refresh test with fake timers
Recommendation: fix now

In app/src/modules/engineering/View.browser.test.ts:157–164, the new test sets fleetFail and waits up to 2500 ms for the real setInterval(tick, 1000) in View.svelte:77 to fire. It never installs fake timers or explicitly advances the poll. Both test runs passed, but this case still depends on the browser scheduling a real one-second timer within the assertion's timeout. It also adds a real second to each isolated run.

CONTRIBUTING.md's Tests / Determinism rule explicitly requires timer-driven code to use fake timers, and applies to every new or changed test. Install vi.useFakeTimers({ toFake: ["setInterval", "clearInterval"] }) before rendering, then advance the timer by 1000 ms after setting fleetFail and await the failure state. The existing Settings status-poll test in app/src/modules/settings/View.browser.test.ts:163–176 demonstrates this pattern. Keep the empty-success followed by failed-refresh assertions; no production change or wider timeout is needed.
