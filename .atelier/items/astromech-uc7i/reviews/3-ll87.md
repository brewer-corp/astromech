## Finding 2: Honor a cold Route link after the saved Text size is restored
Recommendation: fix now

`app/src/App.svelte:71-75` consumes `showOnStart` as soon as the frame has a width, although `startScale()` is still restoring Text size asynchronously. If the initial 100 percent size docks the sidebar but the saved size puts the window below the dock width, `follow.show()` unfolds it in docked mode and leaves `follow.overlay` false. When the settings reply changes `scale.step`, the dock disappears and no overlay opens. The one-time request has already been discarded.

Reproduced in Chromium at 1920 x 1080 with `/?core=ready&route=exact#/route`. At the transport boundary I held the first `window_settings` reply, waited for the sidebar to render, then released that reply with saved `text_size: 115`. Before the reply, the root was 16 px and `.dock` existed. Afterwards, the root was 18.4 px, the route strip was visible, and both `.dock` and `.over` were absent; the address was `#/controller`. The window is now only about 1,670 px at 100 percent, below `DOCK = 1756`, so the cold link must leave the sidebar open as an overlay. `/tmp/uc7i-r3-cold-route-saved-scale.png` captures the result. This reproduces by controlling reply order, without sleeps or changing source files.

This violates the cold-link Done when line at a saved Text size that changes the docking decision. The current every-step layout test sets Text size before mounting, so it cannot catch settings arriving after the initial open. Preserve the initial open request until the saved size has been applied, or reconcile that request when initial settings change docking mode, and cover this delayed settings reply in the cold-link browser case.
