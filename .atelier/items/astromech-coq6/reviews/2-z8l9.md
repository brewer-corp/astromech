## Finding 2: Keep bridge-check shutdown from flooding a passing check with scan errors
Recommendation: defer

`app/dev/bridge-check.ts:18` starts Vite with its normal dependency discovery, although this check only posts to the dev bridge. The finally block closes the server as soon as the bridge assertions finish, while that scan can still be running. In this review, `pnpm bridge-check` printed its success message and exited 0, then logged “Failed to run dependency scan” and hundreds of lines of “The server is being restarted or closed. Request is outdated” from `vite:dep-scan`. This makes a passing check look broken and buries useful errors.

Avoid starting the unnecessary dependency scan for this bridge-only check, or settle its lifecycle before closing the server. This script is unchanged by the item and the bridge assertions passed, so this is later tooling work rather than a merge blocker for Now.
