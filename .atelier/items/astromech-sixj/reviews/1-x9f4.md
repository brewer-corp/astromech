## Finding 1: Rich tips remain visible after dismissal and component removal
Recommendation: fix now

`app/src/design/tokens.css:105` sets `.tip.rich { display: flex }` after `.tip[hidden] { display: none }` at line 100. Both selectors have equal specificity, so the rich rule wins even when Tip sets `hidden`. StationKind and the engineer access marks already use object content and therefore take this path. With the actual stylesheet loaded, hovering a station-type target and leaving, pressing Escape, or running the attachment cleanup leaves the tooltip visibly rendered: `hidden` is true, computed display is `flex`, and its height remains 38.25 px. Since the shared box stays in document.body, it can survive navigation with stale text. Make the hidden rule win for rich tips. Verify rendered visibility with tokens.css loaded; the current tests filter on the hidden property and cannot catch this.
