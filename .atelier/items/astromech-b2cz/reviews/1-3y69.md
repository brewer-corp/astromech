## Finding 1: A failed first-run or migration save is permanently treated as successful
Recommendation: fix now

`app/src/lib/scale.svelte.ts:75-78` applies the picked step, discards the `set_window` result, and resolves `started` to true even when the core returns `{ok:false,error}`. Subsequent status polls then reuse that resolved promise and cannot finish the save. The core explicitly returns failures for config-write errors (`crates/astromech-core/src/app.rs:889-904`), so an unsuccessful write is not an exceptional promise rejection that would escape this path.

I reproduced both an absent choice and legacy `normal` on a simulated 2560 x 1440 display. With `window_settings` succeeding and `set_window` returning a config-write failure, `startScale()` returned true and drew 145%. After allowing writes to succeed, calling it again still returned true without another read or write. The saved values remained null and `normal`, respectively. There was no visible error. Thus the promised one-time persisted selection/migration has not happened; reopening can pick a different size on another display.

Check and handle the save reply. A failed persistence operation must remain observable and must not mark initialization complete as though the choice had been saved. Cover the failed-save path, including recovery, at the transport boundary.
