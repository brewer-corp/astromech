## Finding 3: Preserve plotter flags when NavRoute omits a star class
Recommendation: fix now

`crates/astromech-core/src/route.rs:563-564` selects the NavRoute hops wholesale, and line 583 builds each jump solely from that list. `nav_of` (lines 593-596) gives those hops no scoopable or neutron flag. When a hop's optional star class is absent, this discards flags already supplied for the same system by the exact plotter, so the timeline says unknown despite having the answer. This misses the required class-then-plotter-flag fallback.

Reproduction through the real core: start a temporary preview world in Sol with NavRoute containing Sol and `Tascheter Sector MN-T b3-6`, omitting the latter's `StarClass`. Follow `app/src/preview/fixtures/plot.json`'s recorded exact route through `route_set`. Its first leg correctly selects `hops_from: nav_route` and position 0, but `stops[1].hops[0]` has `scoopable: unknown` and `neutron: null`. The recorded plotter hop for that same system has `scoopable: true` and `neutron: false`; `stops[1].scoopable` even remains `yes`, making the stop and its listed jump disagree.

Keep NavRoute's list and classes first, and retain known plotter flags for matching systems when resolving missing classes. Leave jumps without either source of information unknown. Add a regression using the recorded exact route with the optional NavRoute class absent, alongside the existing case where neither source has a flag.
