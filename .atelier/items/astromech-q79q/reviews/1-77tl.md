## Finding 1: Refresh the current ship when its loadout changes without a ship swap
Recommendation: fix now

`app/src/lib/ui/StatusBar.svelte:32-36` reads the fleet again only when it is absent or `ship_status.ship_id` differs from the cached current ship. Outfitting or engineering the current ship produces a new `Loadout` with the same ID and a changed `MaxJumpRange`; `FleetBuilder::apply` updates that value (`crates/astromech-engineering/src/fleet.rs:173-212`), but this component never asks for the updated reply. Subsequent status ticks and page navigation leave the old jump range in the bar until the window is reopened or another ship is flown. The same cache also keeps an old name when a later Loadout changes it.

I reproduced this at the transport boundary: after the initial recorded ship 3 reply, I made the next fleet reply contain a changed name and range for ship 3, then advanced three 2 s ticks. `ship_status` was called three times, `engineering_fleet` zero times, and the footer still showed `Heavy Lifter` and `Jump 18.0 ly`. Invalidate or refresh this cache for a changed Loadout as well as a changed ship ID, and cover a same-ID range change with a browser regression test.
