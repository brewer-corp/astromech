## Finding 1: The empty preview does not represent a commander with no engineer progress
Recommendation: defer

The real core instead marks the common-knowledge engineers known and actionable; the new no-progress Rust test verifies that. This means the preview cannot validate the actual no-progress page and can display internally inconsistent panels.

The all-locked preview predates this change, the Report identifies it, and the production core has the correct behaviour, so it need not block this item. Follow up by recording a genuine empty-world unlock fixture and using that complete reply instead of rewriting only three fields.
